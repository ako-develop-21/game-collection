# カタン：マルチプレイヤー実装計画

このドキュメントは、現在のCPU対戦型カタンを、Firebase Realtime Databaseを使用してリアルタイムマルチプレイヤー対戦へ変換するための戦略をまとめたものです。

## 前提条件

- 1人プレイヤーとマルチプレイヤーはいずれも遊べることが最終目標。
- 1人プレイの際は、Firebaseを用いた通信処理は行わない。

## フェーズ 1: インフラとルーム管理

**目標**: 通信レイヤーの確立と、プレイヤーが共有ルームに参加できるようにすること。

- [ ] **Firebaseのセットアップ**:
  - `firebase/app` および `firebase/database` の統合。
  - 参照プロジェクトの構成を再利用。
- [ ] **ロビーとルームシステム**:
  - タイトル画面に「マルチプレイヤー」オプションを追加。
  - ルームID生成（ランダム6文字）とURLベースの参加 (`?room=XYZ`) の実装。
  - **プレイヤーリストの同期**: ルーム内にいるプレイヤー（名前、色）の同期。
- [ ] **ホスト選定**: ルームに最初に参加したプレイヤーを「ホスト」（Player ID 0）とする。

## フェーズ 2: ゲーム状態の同期（コア）

**目標**: マップデータと基本的なターンの流れを同期すること。

- [ ] **ボードデータの同期**: ホストがランダムなマップ（タイル、数字、港）を生成し、Firebaseにプッシュ。他のクライアントはそのデータを取得して同じボードを初期化。
- [ ] **ターンの同期**: `currentPlayerId` と `turnPhase` の同期。
- [ ] **プレイヤー情報のマッピング**: 各クライアントを4つのプレイヤースロットのいずれかに割り当て。空きスロットは必要に応じてCPU（AI）が担当。

## フェーズ 3: アクションと資源の同期

**目標**: ダイスロールや建設アクションを同期すること。

- [ ] **アクションバスの実装**: Firebase上の構造化された「actions」ノードを使用して、すべての動き（例：`buildSettlement`, `rollDice`）をログ記録・同期。
- [ ] **プライバシーレイヤー**:
  - **公開データ**: `points`, `資源合計枚数`, `各種ボーナス（最大騎士力等）`, `使用済み発展カード`を同期。
  - **非公開データ**: `詳細な資源配分`と`未プレイの発展カード`は、そのプレイヤーのみがアクセス可能なノードに配置するか、論理的に他者から隠蔽する。
- [ ] **検証**: アクションが `currentPlayerId` 本人からのものであることを確認して受け入れる。

## フェーズ 4: 複雑なルールとカード

**目標**: 資源半分捨て、盗賊の移動、発展カードの処理。

- [ ] **「7」の資源捨て**: ダイスで7が出た際、対象者全員がカードを選択して捨てるのをリアルタイムで待機・処理。
- [ ] **盗賊の移動**: 盗賊が配置された位置と、誰から資源を奪ったかを同期。
- [ ] **発展カード**: カードの購入と使用を同期。

## フェーズ 5: トレードと磨き込み

**目標**: プレイヤー間トレードの実装とUIのブラッシュアップ。

- [ ] **トレードポータル**: プレイヤー間でのトレード提案と受諾をリアルタイムで処理。
- [ ] **ステータス表示**: 誰が現在行動中か、ネットワーク待機中かを表示。
- [ ] **エラーハンドリング**: プレイヤーの切断・再接続の処理。

---

## 技術的アプローチ

- **同期パターン**: `isInternalUpdate` フラグを使用して、無限ループ（循環更新）を防止。
- **データ構造**: `CatanState` 全体または差分をシリアライズしてFirebaseとやり取り。
- **リファレンス**: `electron-image-viewer2` (`IV0002.vue`, `IV0003.vue`) の実装パターンを継承。
