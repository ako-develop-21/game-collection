## 🚀 実装フェーズ（詳細）

### Phase 1: 基礎拡張（システム改修なし）
既存の機能（ドロー、アクション増加、シンプルな選択）で完結するカード群。

- [x] **公爵 (Duke)**: 勝利点計算（公領枚数依存）
- [x] **貧民街 (Shanty Town)**: 条件付きドロー
- [x] **共謀者 (Conspirator)**: アクション数に応じた自己強化
- [x] **製粉所 (Mill)**: 手札廃棄によるコイン獲得（勝利点付き）
- [x] **執事 (Steward)**: 3択（ドロー、コイン、廃棄）
- [x] **貴族 (Nobles)**: 2択（ドロー、アクション、勝利点付き）
- [x] **大広間 (Great Hall)**: +1カード、+1アクション（勝利点付き）
- [x] **ハーレム (Harem)**: 2コイン獲得（勝利点付き）
- [x] **偵察員 (Scout)**: 山札から勝利点カードを引く

### Phase 2: プロンプト連鎖・既存アタックの応用
`allowedCost` や `exactCost` 等のプロンプト拡張、または既存アタックの組み合わせで実装可能なカード。

- [x] **男爵 (Baron)**: 屋敷廃棄/獲得の選択
- [x] **交易場 (Trading Post)**: 手札2枚廃棄、銀貨を手札に獲得
- [x] **改良 (Upgrade)**: 1枚廃棄し、**ちょうどコストが1高いカード**を獲得（`exactCost` 対応済）
- [x] **パトロール (Patrol)**: 4枚めくり、勝利点/呪いを手札、残りを山札へ（再送順UI対応済）
- [x] **拷問人 (Torturer)**: 被アタック者が「2枚捨て」か「呪い手札獲得」を選択
- [x] **寵臣 (Minion)**: アタックと自身の手札リフレッシュ（4枚ドロー/コイン）の複合処理
- [x] **手先 (Pawn)**: 4択から異なる2つを選択（マルチチョイス）
- [x] **廷臣 (Courtier)**: 手札のカードの種類数に応じたマルチチョイス
- [x] **鉄工所 (Ironworks)**: 獲得したカードの種類に応じたボーナス
- [x] **秘密の部屋 (Secret Chamber)**: 手札廃棄によるコイン ※通常効果のみ
- [x] **銅細工師 (Coppersmith)**: 銅貨の発生コイン増加（※ターンフラグ管理）
- [x] **中庭 (Courtyard)**: +3ドロー、手札1枚を山札の上へ
- [x] **鉱山の村 (Mining Village)**: +2アクション、廃棄による追加コイン
- [x] **貢物 (Tribute)**: 左隣のプレイヤーの山札公開に応じたボーナス

### Phase 3: 全体システム・新規UIの拡張（高難度）
ゲームエンジンの基盤（コスト計算、割り込み処理）の改修や、専用UIが必要なカード。

- [ ] **秘密の部屋 (Secret Chamber)**: アタックへのリアクション（手札入れ替え） ※リアクション効果
- [ ] **橋 (Bridge)**: ターン中の全カードコスト軽減（コスト計算ロジックの改修が必要）
- [ ] **外交官 (Diplomat)**: アタック時の割り込みリアクション（進行ボタンUIへの影響大）
- [ ] **潜伏工作員 (Lurker)**: サプライ/廃棄置き場のアクションカードを対象とする獲得処理
- [ ] **仮面舞踏会 (Masquerade)**: 複数人同時カード受け渡し（同期処理）
- [ ] **詐欺師 (Swindler)** / **破壊工作員 (Saboteur)**: 他者のカードを強制的に廃棄・変換させる処理
- [ ] **秘密の通り道 (Secret Passage)**: 山札の「任意の場所」へ戻すUI
- [ ] **願いの井戸 (Wishing Well)**: カード名を推測するテキスト入力/検索UI

### Phase 3: 詳細実装ステップ

Phase 3 はシステム基盤への影響が大きいため、以下の 4 ステップに分けて段階的に実装・検証を進めます。

#### Step 1: リアクション・割り込みシステムの構築
他プレイヤーのターン中に発生するアタックに対し、手札を公開して効果を得るための汎用基盤を実装します。

- **対象**: **秘密の部屋** (リアクション効果)、**外交官**
- **開発内容**:
    - `Attack` 発生時に全プレイヤーの手札を確認するフックの追加。
    - 堀（Moat）のような自動防御ではない、選択を伴うリアクション用プロンプトの管理。
    - 他者のターンにおける手札入れ替え等の状態更新ロジックの安定化。

#### Step 2: 動的コスト計算システムの導入
カードのコストが状況に応じて変動する仕組みをエンジンに組み込みます。

- **対象**: **橋**
- **開発内容**:
    - `getCardCost(cardId, state)` 関数を新設し、静的な `card.cost` 参照を置換。
    - ターン状態（`bridgeCount` 等）によるコスト減算ロジックの実装。
    - サプライ表示や購入判定時のリアルタイムコスト反映。

#### Step 3: 特殊な獲得・移動処理の拡張
サプライ以外（廃棄置き場）からの獲得や、山札の任意位置への配置など、既存プロンプトの制限を超えた処理を実装します。

- **対象**: **潜伏工作員** (サプライ/廃棄置き場からの獲得)、**秘密の通り道** (山札の任意箇所へ挿入)
- **開発内容**:
    - `ActionPrompt` に `targetSource` (trash, supply, etc.) プロパティを追加。
    - 山札の特定 Index にカードを挿入する `insertAt` ヘルパーの実装。

#### Step 4: 同期・特殊UI処理の統合
複数人の同時操作や、広範なカードリストからの検索など、高度な UI/ロジックを実装します。

- **対象**: **仮面舞踏会** (同時交換)、**詐欺師/破壊工作員** (他者のカードの強制変換)、**願いの井戸** (カード名推測)
- **開発内容**:
    - 非同期プロンプトの同期マージ処理（複数プレイヤーの回答待ち）。
    - 自由入力またはリスト検索によるカード名指定 UI の作成。
    - アタック者が「他者のための獲得」を代行するプロンプトの拡張。
